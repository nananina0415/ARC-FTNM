# 프로젝트 메모리

## 설계 원칙 — 최소 목표는 완성된 CPU의 부분집합

사용자가 최소 목표를 제시하더라도, 그 목표를 맞추기 위한 전용 회로나 실행
시나리오를 하드코딩하지 않는다. 이 프로젝트의 목표는 전체 MMIX CPU이며,
각 단계의 구현은 완성된 CPU에 그대로 포함될 수 있는 부분집합이어야 한다.

- 최소 목표는 지금 지원할 기능과 개발 순서를 정한다. 모듈의 책임과 CPU의
  일반적인 동작 원리를 예제에 맞게 축소하거나 대체하라는 뜻이 아니다.
- 디코더는 명령어 해석, 제어유닛은 실행 흐름, 연산 유닛은 계산, 레지스터와
  메모리 모듈은 상태와 데이터 접근을 맡는다. 모듈을 나눈 목적을 유지한다.
- 동작은 명령어·데이터·CPU 상태·정의된 제어신호에서 나와야 한다.
  예제의 프로그램 내용·실행 횟수·명령어 위치·기대 결과를 회로에 넣지 않는다.
- 미지원 기능은 경계를 명확히 하고 이후 확장할 수 있게 둔다. 현재 필요한
  기능은 실제 모듈과 실행 경로로 구현하며, 미래 기능을 미리 모두 만들지는 않는다.
- 새 기능을 추가할 때 예제 전용 구현을 버리고 전체 흐름을 다시 만들어야 한다면
  최소 목표를 잘못 해석한 것이다. 기존 구조를 확장할 수 있는지 기준으로 판단한다.
- 리셋 벡터, 명령어 인코딩, 보드 인터페이스 폭 같은 설계 상수와 예제 전용
  하드코딩은 구분한다.

2026-11-02 사용자 지적의 핵심: 특정 ADD/HALT 사례의 수정에 한정된 규칙이 아니라,
프로젝트 전체에서 모든 최소 목표를 해석하고 구현할 때 적용하는 원칙이다.

## 작업 제약

동작 확인은 사용자가 직접 한다. 사용자가 명시적으로 요청하지 않으면
테스트·시뮬레이션·합성·보드 실행을 수행하지 않는다.
