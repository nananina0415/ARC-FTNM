# 의사코드 언어 명세 v0.1

이 문서는 사용자가 권장안 적용을 요청한 데 따라 정한 언어·변환 규칙이다.
[grammar.peg](grammar.peg)는 구문, 이 문서는 타입·회로 의미,
[grammar.md](grammar.md)는 읽기 쉬운 설명이다. 구문 분석 성공만으로 유효한 회로는 아니다.

## 1. PEG 표기와 문장 경계

- grammar.peg는 특정 파이썬 라이브러리에 종속되지 않는 PEG 명세다.
  `<-`는 규칙 정의, `/`는 순서 있는 선택, `!`는 부정 lookahead다.
- 작은따옴표는 문자열, 대괄호는 문자 집합, `.`은 임의 문자다.
  `?`, `*`, `+`는 선택/0회 이상/1회 이상이며 `\uFEFF`는 BOM 문자다.
- 파일은 UTF-8, 선택적 BOM과 CRLF/LF/CR 줄바꿈을 허용한다.
  식별자는 ASCII 영문·숫자·밑줄이며 대소문자를 구분한다. 주석은 `//`부터 줄 끝까지다.
- 줄바꿈과 들여쓰기는 공백이다. 파서는 선언·연결·표현식의 모양으로 문장 경계를 찾는다.
  따라서 한 문장을 여러 줄에 쓰거나 완성된 문장들을 같은 줄에 쓸 수 있다.
- 표현식에 붙을 수 있는 연산자·필드·인덱스는 줄이 바뀌어도 이어 읽는다.
  구문상 이어지지 않는 다음 선언/연결은 새 문장이다. 세미콜론은 배열 타입의 길이
  구분자로만 사용하며, 줄 연결 기호나 문장 종료 기호로 요구하지 않는다.
- 완성된 연결 우변 또는 alias 우변 뒤 새 줄의 packed 목록 `[ ... ]` 다음에 화살표가
  있으면 새 배선 문장으로 우선 해석한다. 이는 ALU 결과 목록 배선이 앞 문장의
  인덱스로 붙는 모호성을 해결한다. PEG의 RightReference/NewPackedStatement 규칙이다.
  좌변 인덱싱은 이 제한을 받지 않는다. 우변의 다중 줄 인덱싱을 명확히 표현해야 하면
  전체 참조를 괄호 안에 넣을 수 있다.
- 줄바꿈을 제거한 문장이 여러 의미를 갖게 쓰인 경우 의도를 추측하지 않는다.
  PEG의 우선순위로 의미를 정하고, 다른 의도는 괄호로 명시한다.
- alias/번들 목록은 요소 사이 쉼표를 생략할 수 있고 마지막 쉼표도 허용한다.
  함수 인자·제네릭 인자·비트 목록은 쉼표가 필요하다.
- 블록, 대상 목록, packed 목록과 배열 타입은 각각 다른 AST 노드다.
  lexer가 모든 중괄호 내용을 같은 것으로 처리하지 않는다.

현재 제네릭 인자는 정수 상수 또는 타입이다. PEG는 넓은 Expression으로 받으며,
소자 선언의 파라미터 종류와 대조해 의미 분석에서 구분한다. 일반 함수 호출은
허용하지 않고 and/or/not/xor 게이트만 허용한다.

## 2. 이름과 선언

- 폴더가 이름 공간이다. 파일을 경로순으로 수집하되 이름 해석은 선언 순서와 무관하다.
- 같은 이름 공간의 선언을 먼저 수집한 뒤 참조와 alias를 해석한다. 중복 선언과
  alias 순환은 오류다. comb/seq와 같은 이름의 wire는 정확히 하나씩 있어야 한다.
- 로컬 파라미터/alias, 현재 이름 공간, global, 내장 순서로 탐색한다.
  타입·값·회로 인스턴스를 구별하고 문법에 맞지 않는 종류의 참조는 오류다.
- 하위 `::child::Name`, 형제 `sibling::Name` 규칙은 grammar.md를 따른다.
  global에서 `::`는 소스 루트의 하위 이름 공간을 가리킨다. 상위 참조는 지원하지 않는다.
- 인자 없는 alias와 제네릭 기본형은 arity로 구분한다. `alias TriState = TriState<64>`에서
  오른쪽은 인자 1개를 받는 내장 타입이다. 같은 이름의 인자 없는 alias로 재귀하지 않는다.
  이 규칙은 TriState 이름만을 위한 특례가 아니다.
- 별칭은 참조 대상의 종류·폭·방향을 유지한다. 타입 alias를 신호처럼 사용할 수 없다.
- 반환 타입 없는 재귀 회로 인스턴스, 재귀 번들, 무한한 제네릭 확장은 오류다.

## 3. 값·타입·폭

- 초기 scalar 타입은 bit만 지원하며 신호 벡터는 unsigned다.
- 상수 식은 정수와 단항 +/-, 이항 +,-,*,/,%를 지원한다. 이항 *,/,%가 +,-보다
  우선하고 같은 우선순위는 왼쪽 결합이다. 상수 나눗셈은 0 방향으로 절삭하며,
  나머지는 a - trunc(a/b)*b다. 상수 0 나눗셈은 오류다.
- 신호에 위 산술 연산자를 적용하지 않는다. 런타임 산술은 Adder 등 소자로 명시한다.
- 정수 상수는 임의 정밀도로 계산하고, 신호 폭·배열 길이는 양의 정수여야 한다.
- 10진수, 0x 16진수, 0b 2진수를 지원한다. 음수는 단항 - 식으로 표현한다.
- 목적지 폭 W의 상수 연결은 0 <= 값 < 2^W만 허용한다. 음수·초과는 오류다.
  음수 비트 패턴은 비트 배선 또는 반전 등으로 명시한다.
- 일반 배선은 폭 일치를 요구하며 확장·잘림을 자동 삽입하지 않는다.
- `word <- 1`은 수치 1의 W비트 표현이다. `{ word[..] } <= 1`은 각 1비트에 1을 연결한다.
- 배열 타입과 packed 비트 벡터는 구분한다. 배열을 하나의 벡터로 쓸 때는 `[ ... ]`로 묶는다.

## 4. 비트·배열·게이트

- bit 0이 최하위 비트다. 범위는 [a,b), 증가 순서로 전개한다.
- 나열한 첫 요소가 결과의 하위 비트다. `[a,b]`의 Verilog 표현은 `{b,a}`에 해당한다.
- `x[..]`는 현재 선택 대상 전체, `x[a,b,c]`는 나열 순서다. 배열 필드도 인덱스 순으로 전개한다.
- 범위 밖·역방향·빈 범위·목적지 중복 비트는 오류다. 중복 소스 비트는 허용한다.
- 게이트 인자에서 인덱싱 결과는 가닥 목록으로 전개한다. `x[i]`는 가닥 하나다.
  `[x[..]]`는 명시적으로 묶은 벡터이며, 인덱스 없는 벡터도 벡터 인자다.
- 전개한 가닥들만 있으면 and/or/xor는 1비트 reduction 결과를 낸다.
  벡터 인자들은 모두 폭이 같아야 하며 비트별 연산을 한다. 서로 다른 폭이나
  다비트 벡터와 가닥 목록의 혼합은 오류다. 1비트는 가닥과 호환된다.
- not은 인자 하나만 받아 그 인자 형태에 맞춰 각 비트를 반전한다.
  전개 결과 여러 가닥이면 `[ ... ]`로 먼저 묶도록 요구한다.
- and/or/xor는 전개 후 최소 한 입력을 요구한다. 빈 입력 목록은 오류다.

## 5. 포트와 연결

- pub 포트 방향은 선언 소자의 관점이다. 자식 input은 부모에서 구동할 대상,
  자식 output은 부모에서 읽을 소스다. 현재 모듈 input은 내부에서 소스로 사용한다.
- 연결된 핀의 net은 입력 핀이라도 다른 식에서 읽을 수 있다. 방향은 구동 권한을
  제한하며, 읽기 가능 여부와 혼동하지 않는다. 필수 입력의 구동기 존재는 별도 검사한다.
- `*번들`은 In/Out을 재귀 반전하고 InOut은 유지한다. 포인터나 저장 소자를 생성하지 않는다.
- `->`/`<-`는 같은 폭의 비트별 연결이다. `=>`/`<=`는 목록의 각 대상과 공통 endpoint를
  같은 폭으로 연결한다. `{}`는 복제/공유 연결 목록이고 `[]`처럼 이어 붙이지 않는다.
- 단방향 화살표를 포트 방향 위반을 무시하는 근거로 사용하지 않는다.
  여러 공급원이 공통 endpoint로 모이면 공유 net의 다중 구동 규칙을 적용한다.
- `<=>`는 공유 net을 형성한다. 양방향 assign 두 개로 출력하지 않는다.
- 혼합 방향 번들 전체의 화살표 연결은 v0.1에서 허용하지 않는다.
  복합 번들은 leaf 포트끼리 명시적으로 연결한다. 향후 전체 연결 문법을 별도로 추가할 수 있다.
- net마다 일반 구동기와 삼상 구동기를 추적한다. 일반 구동기는 최대 하나다.
  삼상 공유 net에는 여러 TriState 출력을 허용하고, 일반 구동기와 함께 있으면
  enable에 따른 충돌 가능성을 진단하되 임의의 우선순위를 만들지 않는다.
- 삼상 구동기들이 같은 값을 내면 그 값, 모두 꺼지면 Z, 충돌하면 X라는
  4상태 RTL 의미를 유지한다. FPGA 물리 구현은 합성기에 맡긴다.
- 모든 구동기를 하나로 모은 공유 net을 표현한 뒤 방향·중복을 검사한다.
  bus 연결 표현 자체를 여러 개의 역방향 assign으로 치환하지 않는다.

## 6. 저장과 표준 소자

- comb/seq 모두 module로 출력한다. seq 전체가 클록 always 블록인 것은 아니다.
- seq 인스턴스는 mut가 필요하다(SyncRam 포함). 원시 내장 D_FlipFlop은 mut 없이 선언하는 예외이며,
  DFF 포함 여부는 순차성 검사에 여전히 반영한다. comb의 직접/간접 순차 소자 포함은 오류다.
- clock/reset/초기화는 소스가 명시한다. 변환기가 자동 reset이나 초기값을 삽입하지 않는다.
- 순차 피드백은 허용하지만 순수 조합 루프는 오류다.

| 소자 | v0.1 계약 |
|---|---|
| D_FlipFlop | 1비트, 상승 에지에서 in 저장. 내부 reset/초기값 없음 |
| Mux<n,m> | n,m 양수. 선택 폭 max(1,ceil(log2(n))). n개의 m비트 입력 중 선택 |
| Decoder<i,o> | i,o 양수, o <= 2^i. 입력값에 해당하는 출력만 1. 범위 밖은 모두 0 |
| TriState<N> | N비트. enable=1이면 in, 0이면 Z. unknown enable은 4상태 RTL 의미 유지 |
| Adder<N> | a,b,sum N비트, c_in/c_out 1비트. N+1비트 합의 하위/최상위 분리 |
| Multiplier<N> | a,b N비트. signed=0 unsigned, 1이면 2의 보수 signed 곱. 2N비트 hi/lo |
| PipeMultiplier<N,S> | seq. Multiplier와 같은 곱을 1+S클록 뒤 hi/lo로 낸다. S >= 1. 아래 참고 |
| Divider<N> | dividend 2N비트, divisor N비트 unsigned. quotient/remainder N비트 |
| IterDivider<64> | seq. 64비트 반복 나눗셈. 아래 참고 |
| SyncRam<d,w,l> | d는 2 이상 2의 거듭제곱, w는 l의 배수. 주소 폭 ceil(log2(d)). 아래 참고 |

Divider의 몫이 N비트를 넘으면 하위 N비트로 내보낸다. divisor=0이면 결과는 X다.
관련 MMIX 예외/대체 결과는 Div 회로가 처리하며 표준 소자가 MMIX 명령을 해석하지 않는다.
unknown 제어/산술 입력은 4상태 RTL 의미를 따른다. Decoder의 unknown 입력은 X 출력을 낸다.
조합 소자를 다중 사이클 IP로 바꾸거나 파이프라인을 삽입하지 않는다.

SyncRam<d,w,l>은 d개 칸의 w비트 메모리이며 seq 소자다(mut로 선언).

- 쓰기: 상승 에지에서 `w_en`의 레인 i가 1이면 칸 `w_addr`의 비트 [i*w/l, (i+1)*w/l)에 `w_data`의 같은 비트를 쓴다.
  레인이 l개라 칸의 일부만 바꿀 수 있다(바이트 쓰기 활성화 등).
- 읽기: 상승 에지에서 `r_en`=1이면 칸 `r_addr`의 값을 출력 레지스터에 담고 `r_data`로 내보낸다.
  `r_en`=0이면 출력은 이전 값을 유지한다. 주소를 준 다음 클록부터 값이 보이는 동기 읽기다.
- 같은 에지에 같은 칸을 읽고 쓰면 읽기는 쓰기 전 값을 낸다(read-first).
  새 값이 필요한 회로는 우회 경로를 소스에 명시한다.
- 내용과 출력 레지스터의 초기값은 0이다(FPGA 구성 시 값). reset 입력은 없고 reset으로 지워지지 않는다.
- 주소나 `r_en`이 unknown이면 읽기 결과는 X이고, unknown 주소 쓰기는 어느 칸이 바뀌었는지 보장하지 않는다.
- 변환기는 Vivado 블록 RAM 추론 형태(메모리 배열 + 레인별 쓰기 + 등록 읽기, `ram_style = "block"`)로
  출력한다. 조합 읽기 포트나 두 번째 쓰기 포트는 이 소자에 없다.

PipeMultiplier<N,S>는 매 상승 에지에 a, b, signed를 입력 레지스터에 담고, 그 곱을 S단 레지스터로 넘긴다.
k번째 에지에 넣은 입력의 곱은 k+1+S번째 에지 뒤 hi/lo에 보인다. reset은 없으며 지연 동안의 출력은
이전 입력의 곱이다. 입력·곱·레지스터를 한 모듈에 출력해 Vivado가 DSP48 파이프라인 레지스터로 흡수할 수 있게 한다.

IterDivider<64>는 서드파티 OpenC906 `aq_iu_div`(Apache-2.0, `third_party/T-head-Semi_openc906`)를
수정 없이 인스턴스화한다. 변환기는 이 소자를 쓰면 원본 Verilog 3개를 sources.f에 넣는다.

- `idle`=1일 때 `start`=1인 에지에서 `dividend`, `divisor`, `signed`, `remainder`를 받는다.
  `idle`=0일 때의 `start`는 받지 않는다.
- 결과가 나오는 클록에 `done`=1이 되고 `result`가 유효하다. 다음 에지에서 결과를 내보내고 `idle`로 돌아간다.
- `remainder`=0이면 몫, 1이면 나머지를 낸다. 부호 있는 연산은 몫을 0 쪽으로 자르고 나머지 부호는 피제수를 따른다.
- divisor=0이면 몫은 모든 비트 1, 나머지는 피제수다. signed에서 −2^63 ÷ −1은 몫 −2^63, 나머지 0이다.
- 반복 한 번에 몫 2비트를 내며 앞자리 0만큼 건너뛴다. 최대 약 35클록이다.
  직전 연산과 피연산자·부호가 같으면 1클록에 끝난다(몫 다음 같은 피연산자의 나머지 요청).
- `reset`=1 동안 내부 상태와 직전 피연산자 저장을 지운다.

## 7. OPENED와 미정의

- `output -> OPENED`: 의도적 미사용 출력이다. 빈 인스턴스 출력 포트 또는 미사용 net으로 출력한다.
- `input <- OPENED`: 의도적 열린 입력으로 기록하고 해당 폭의 Z를 연결한다.
  Mux의 OPENED option도 이 규칙을 따른다. X와 Z를 같은 의미로 취급하지 않는다.
- 연결이 아예 없는 필수 input은 오류다. 미사용 output도 OPENED로 명시하도록 요구한다.
- Mux select가 n 이상이거나 unknown이면 selected는 X다. latch나 암묵적 값 유지는 없다.
- X/Z는 실제 하드웨어의 오류 검출 장치가 아니다. 안전한 결과나 오류 신호가 필요하면
  소스 회로로 명시해야 한다. 변환기는 Mux 범위 밖을 자동으로 0 처리하지 않는다.
- DirectReg select=3은 이 계약상 X지만, 동시 쓰기의 우선순위는 여전히 회로 설계 사항이다.

엄격한 미사용 출력 검사는 현재 파일에도 추가 OPENED 표시를 요구할 수 있다.
그 경우 소스 위치를 진단한다. 변환기의 CPU 전용 예외로 숨기지 않는다.

## 8. 출력과 결정론

- 초기 출력은 Verilog-2001이다. 번들은 이름을 펼친 일반 포트로 출력한다.
- 폴더 이름 공간을 유지하고 comb/seq 정의 하나당 module 하나를 생성한다.
  폴더·bundle·alias를 별도 회로 module로 만들지 않는다.
- 제네릭은 템플릿 AST와 구체화된 회로 IR로 관리한다. 초기 출력은 사용된 인자 조합별
  특수화 모듈이고 같은 조합은 한 번 생성한다. 이후 parameter 출력도 같은 구조에서 확장한다.
- module 이름은 이름 공간 경로와 구체 파라미터로 만든다. 인코딩은 충돌 없는 방식으로
  정의하며 단순 밑줄 합치기로 다른 이름이 충돌하게 하지 않는다.
- gate/연결은 assign, DFF는 nonblocking 순차 대입으로 출력한다.
- 단일 파일 옵션도 같은 module 집합을 합칠 뿐 회로 계층을 flatten하지 않는다.
- 입력 순서·이름·인코딩·줄바꿈을 고정하고 시각/절대 경로를 생성 RTL에 넣지 않는다.
- sources.f와 top 정보, 소스 위치 맵, 생성 파일 manifest를 만든다.
- 파싱/의미 분석 실패 시 임의 수정 없이 파일·행·열과 함께 실패한다.
- 합성/시뮬레이션/보드 실행은 변환기의 기본 부수 동작에 포함하지 않는다.

## 9. 적용 범위

이 명세는 회로를 표현하는 언어의 기준이지, 현재 모든 소스가 이미 이 기준을
통과한다는 선언이 아니다. 기존 소스의 미연결 출력·공유 버스·상수 등의 불일치는
변환기 구현 시 일반 진단으로 드러내고 수정한다. 이번 작업에서 회로 동작을 바꾸지는 않는다.
PEG 파서 구현·문법 실행·테스트·합성은 수행하지 않았다.
