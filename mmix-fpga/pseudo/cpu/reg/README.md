# 레지스터 접근

`Registers`는 범용 레지스터의 읽기 2포트·쓰기 1포트와 특수 레지스터 GET/PUT 버스를
제공한다. rA/rD/rH/rM/rR는 ALU 직접 배선과 GET/PUT에서 같은 저장 상태를 사용하고,
rJ/rO/rS/rG/rL은 레지스터 스택 직접 배선과 GET에서 같은 저장 상태를 사용한다.
CPU는 GET/PUT 실행 중 ALU 쓰기를 차단해 두 쓰기 경로가 동시에 활성화되지 않게 한다.

## 레지스터 스택 구조

범용 슬롯은 256개이고 로컬과 글로벌이 공유한다.

| 번호 k | 슬롯 | 읽기 | 쓰기 |
|---|---|---|---|
| k >= G | k | 값 | 값 |
| k < L | (α+k) mod R | 값 | 값 |
| 그 외 (marginal) | 없음 | 0 | L을 늘린 뒤 로컬로 쓴다 |

ring 크기 R은 G 이하에서 가장 큰 2의 거듭제곱으로 32, 64, 128 중 하나다.
`α=(rO/8) mod R`, `γ=(rS/8) mod R`이고 R<=G이므로 ring과 글로벌 슬롯은 겹치지 않는다.
슬롯 R..G-1은 쓰지 않는다. 리셋 값은 L=0, G=255, rO=0, rS=0이다.

사양서(mmix-doc §42)의 두 뱅크 구조 대신 슬롯을 공유한 축소 구현이다. 프로그램이 보는
동작은 다음 범위에서 사양과 같다.

- L은 R-1까지 지원한다. 넘으면 fault_reason bit 1로 정지한다.
- R이 바뀌는 PUT rG는 L=0일 때만 허용한다. 대기 칸을 모두 내보낸 뒤 G를 바꾼다.
- rS 초기값은 UNSAVE가 아니라 리셋 값이다. SAVE/UNSAVE는 아직 구현하지 않았다.
- 가상 메모리와 메모리 보호가 없어 스택 넘침과 바닥 초과를 감지하지 않는다.
- spill 시점이 ring 크기에 따라 달라 공식 시뮬레이터와 rS 값이 다를 수 있다.

번호 변환은 `RegisterWindow`, 포인터와 마스크는 `RingGeometry`가 맡는다.
`stack_w_*`와 `r1_physical`은 StackControl이 슬롯을 직접 지정하는 경로다.
L 증가의 0 쓰기, hole, fill 같은 내부 쓰기는 명령의 $X 쓰기인 `w_en`과 구분한다.

## 특수 레지스터 접근 정책

`SpecialAccess`는 현재 지원 가능한 특수 레지스터와 쓰기 값을 검사한다.

| 대상 | GET | PUT |
|---|---|---|
| 번호 0~7, 21~31 | 허용 | 허용 (rA는 아래 제한) |
| rO, rS | 허용 | 무효 |
| rG | 허용 | 32 이상 255 이하, L 이상, R이 바뀌면 L=0일 때만 |
| rL | 허용 | 허용. 값이 현재 L 이상이면 L을 유지 |
| 번호 8, 9, 12~18 | 무효 | 무효 |

trap 관련 저장 셀을 읽고 쓸 수 있다는 것이 trap 실행 지원을 뜻하지는 않는다.

rA는 4비트 저장 구조다. MMIX 비트 6/7은 V/D 이벤트, 14/15는 각 enable이며
GET은 나머지 비트를 0으로 읽는다. PUT 값에 마스크 `0xc0c0` 밖의 비트가 있으면 거부한다.
거부는 CPU의 decoded_valid에 반영해 실행 전에 무효 명령 fault로 처리한다.

현재 접근 경로와 생성 RTL은 구현했으며 레지스터 스택 추가 후 테스트·시뮬레이션은
실행하지 않았다.
