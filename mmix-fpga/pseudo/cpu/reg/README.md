# 레지스터 접근

`Registers`는 범용 레지스터의 읽기 3포트·쓰기 1포트와 특수 레지스터 GET/PUT 버스를
제공한다. rA/rD/rH/rM/rR는 ALU 직접 배선과 GET/PUT에서 같은 저장 상태를 사용하고,
rJ/rO/rS/rG/rL은 레지스터 스택 직접 배선과 GET에서 같은 저장 상태를 사용한다.
CPU는 GET/PUT 실행 중 ALU 쓰기를 차단해 두 쓰기 경로가 동시에 활성화되지 않게 한다.

## 저장 위치

| 대상 | 저장 | 비고 |
|---|---|---|
| 범용 슬롯 512개 | 블록 RAM 3벌 (`SyncRam<512,64,1>`, 각각 RAMB36 하나) | 쓰기는 세 벌에 함께, 읽기 포트 r1($Y·분기/상수의 $X·스택 슬롯), r2($Z), x(store $X) |
| GET/PUT 전용 특수 레지스터 | 블록 RAM 1개 (`SyncRam<32,64,1>`) | rB rE rBB rC rN rI rTT rK rQ rU rV rF rP rW rX rY rZ rWW rXX rYY rZZ |
| rA rD rH rM rR rJ rO rS rG rL rT | 플립플롭 | ALU·레지스터 스택·TRAP이 직접 배선으로 매 클록 읽는다 |

- 읽기는 동기식이다. 번호를 준 다음 클록에 값이 나오고, 같은 클록에 같은 칸을 쓰면 쓰기 전 값이 나온다.
  Control은 명령마다 READ 한 클록을 거쳐 EXECUTE에서 값을 쓴다.
- marginal 번호는 읽기 번호와 함께 등록해 두었다가 다음 클록 값을 0으로 바꾼다.
- `r1_valid`, `special.valid`: 직전 클록 번호가 지금 번호와 같고 그 클록에 같은 칸을 쓰지 않았으면 1.
  StackControl이 같은 상태 안에서 번호를 바꾸며 읽을 때 쓴다.
- 블록 RAM 내용은 reset으로 지워지지 않는다. FPGA 구성 시 0이다.

## 레지스터 스택 구조

범용 슬롯은 512개다. 슬롯 0..255가 로컬 ring, 256..511이 글로벌이다.

| 번호 k | 슬롯 | 읽기 | 쓰기 |
|---|---|---|---|
| k >= G | 256+k | 값 | 값 |
| k < L | (α+k) mod 256 | 값 | 값 |
| 그 외 (marginal) | 없음 | 0 | L을 늘린 뒤 로컬로 쓴다 |

ring 크기는 G와 무관하게 256이다. 공식 시뮬레이터(mmix-sim.w)의 기본 ring 크기와 같다.
`α=(rO/8) mod 256`, `γ=(rS/8) mod 256`은 rO, rS의 비트 [3..11] 그대로다.
슬롯 256..256+G-1은 쓰지 않는다. 리셋 값은 L=0, G=255, rO=0, rS=0이다.

동작은 다음 범위에서 사양과 같다.

- L은 사양대로 G까지 쓸 수 있다. G<=255이므로 ring을 넘지 않는다.
- PUT rG는 32 이상 255 이하, L 이상이면 허용한다. 새로 글로벌이 된 칸을 0으로 만든다.
- SAVE/UNSAVE는 사양의 저장 형식을 따른다. UNSAVE는 hole의 k개 로컬을 모두 읽고 L←min(k, G)이다.
- rA는 저장 칸의 비트 6, 7, 14, 15만 복원한다. 나머지 비트는 버린다.
- 인터럽트가 없어 SAVE/UNSAVE는 끝까지 실행된다.
- 가상 메모리와 메모리 보호가 없어 스택 넘침과 바닥 초과를 감지하지 않는다.
- spill 조건(ring이 꽉 참)은 공식 시뮬레이터와 같다. 한 번에 옮기는 칸 수가 달라(아래)
  spill 횟수와 rS 값은 다를 수 있다.

## spill/fill 단위

spill/fill은 32바이트 라인(캐시 라인과 AXI 1회 전송 크기) 안의 연속 칸을 한 번에 옮긴다.
공식 시뮬레이터(mmix-sim.w의 stack_store/stack_load)는 1워드씩 옮긴다.

- spill: ring이 꽉 차면 min(미저장 칸 수, rS부터 라인 끝까지 칸 수)칸을 쓰기 1회로 내보내고
  rS를 8×칸 수만큼 올린다. rS가 32바이트 정렬이고 미저장 칸이 4개 이상이면 4칸이다.
  현재 프레임의 로컬은 내보내지 않으므로 미저장 칸이 4개보다 적으면 있는 만큼만 내보낸다.
- fill(POP): min(라인 시작부터 rS 앞까지 칸 수(rS 정렬이면 4), ring 빈칸 수)칸을 읽기 1회로
  가져오고 rS를 그만큼 내린다. POP에 필요한 칸보다 오래된 칸을 최대 3칸 더 가져올 수 있다.
- UNSAVE의 로컬 복원과 SAVE/UNSAVE의 글로벌·특수 레지스터는 1워드씩 옮긴다.
- rS가 정렬되지 않았으면 다음 전송은 라인 경계까지만 옮기므로 이후 정렬된다.
  BIOS는 32바이트 정렬된 rS로 UNSAVE한다.
- 프로그램이 보는 레지스터 값은 1워드씩 옮길 때와 같다. 같은 양을 AXI 쓰기 약 4분의 1로 처리한다.
- fill로 더 가져온 칸 때문에 곧 다시 spill이 일어날 수 있다.

번호 변환은 `RegisterWindow`가 맡는다. 슬롯 번호는 9비트이고 비트 8이 글로벌 여부다.
리셋 직후 rS=0이므로 spill을 쓰는 소프트웨어는 UNSAVE로 rS를 먼저 설정해야 한다.
`stack_w_*`와 `r1_physical`은 StackControl이 슬롯을 직접 지정하는 경로다.
L 증가의 0 쓰기, hole, fill 같은 내부 쓰기는 명령의 $X 쓰기인 `w_en`과 구분한다.

## 특수 레지스터 접근 정책

`SpecialAccess`는 현재 지원 가능한 특수 레지스터와 쓰기 값을 검사한다.

| 대상 | GET | PUT |
|---|---|---|
| 번호 0~7, 21~31 | 허용 | 허용 (rA는 아래 제한) |
| rT, rK | 허용 | 허용. 권한 검사는 아직 없다 |
| rO, rS | 허용 | 무효 |
| rG | 허용 | 32 이상 255 이하, L 이상 |
| rL | 허용 | 허용. 값이 현재 L 이상이면 L을 유지 |
| 번호 8, 9, 12, 14, 16~18 | 무효 | 무효 |

trap 관련 저장 셀을 읽고 쓸 수 있다는 것이 trap 실행 지원을 뜻하지는 않는다.

rA는 4비트 저장 구조다. MMIX 비트 6/7은 V/D 이벤트, 14/15는 각 enable이며
GET은 나머지 비트를 0으로 읽는다. PUT 값에 마스크 `0xc0c0` 밖의 비트가 있으면 거부한다.
거부는 CPU의 decoded_valid에 반영해 실행 전에 무효 명령 fault로 처리한다.

SAVE의 $X는 글로벌이어야 하며 아니면 같은 방식으로 무효 명령 fault가 된다.

현재 접근 경로와 생성 RTL은 구현했으며 블록 RAM 전환 후 테스트·시뮬레이션은
실행하지 않았다.
