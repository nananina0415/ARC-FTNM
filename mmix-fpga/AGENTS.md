# 프로젝트 작업 지침

## 작업 전 확인

- [MEMORY.md](MEMORY.md)의 사용자 지적과 설계 결정을 읽고 작업에 반영한다.
- 기존 회로 의사코드 문법은 `pseudo/grammar.md`를 따른다.

## 확장을 전제로 구현

- 목표는 전체 MMIX CPU 구현이다. 최소 목표를 제시받으면 완성된 CPU의 부분집합을 구현한다. 최소 목표는 지원 범위와 개발 순서를 제한하며, 아키텍처를 예제 전용으로 바꾸라는 뜻이 아니다.
- 각 모듈은 완성된 CPU에서도 사용할 책임과 인터페이스를 유지한다. 디코더, 제어유닛, 연산 유닛, 레지스터, 메모리 접근의 역할을 예제 전용 논리 하나로 대체하지 않는다.
- 프로그램의 내용, 실행 횟수, 명령어 배치나 기대 결과를 회로에 하드코딩하지 않는다. 동작은 명령어, 데이터, CPU 상태 및 정의된 제어신호에 따라 결정한다.
- 기능을 추가할 때 기존 예제 전용 회로를 폐기하고 재작성해야 한다면 최소 목표의 구현 방향부터 다시 검토한다. 기존 모듈과 실행 경로에 기능을 추가할 수 있는 구조로 만든다.
- 리셋 벡터, 명령어 인코딩, 실제 보드 인터페이스 폭처럼 명시된 설계 상수는 구분한다. 예제를 맞추기 위한 하드코딩 금지와 혼동하지 않는다.
- 지금 필요한 부분을 기존 구조에 연결하되, 요청하지 않은 명령어와 기능까지 구현 범위를 확대하지 않는다.

## 동작 확인

- 사용자가 명시적으로 요청하지 않으면 테스트·시뮬레이션·합성·보드 실행 등 동작 확인을 수행하지 않는다.
- 동작 확인은 사용자가 직접 한다. 사용자가 명시적으로 요청한 경우에만 수행한다.
- 실행하지 않은 테스트나 보드 확인을 완료했다고 보고하지 않는다.
