# 의사코드 → Verilog 변환기: 필요한 결정

작성일: 2026-11-02

## 적용 상태

사용자의 권장안 적용 요청에 따라 v0.1 구문을 [grammar.peg](../pseudo/grammar.peg),
의미·소자·출력 규칙을 [language-semantics.md](../pseudo/language-semantics.md)에 정리했다.
아래 목록은 최초 검토와 대안을 보존한 것이다. 현재 기준은 두 명세와 grammar.md를 따른다.
특히 열린 입력은 Z, Mux 범위 밖 선택은 X, 원시 DFF는 mut 예외,
초기 출력은 Verilog-2001과 제네릭 구체 특수화를 선택했다.
DirectReg의 쓰기 우선순위 같은 회로 설계 결정은 언어 명세가 대신하지 않는다.
파서 구현과 테스트는 아직 수행하지 않았다.

## 1. 목적과 문서 상태

현재 `.pseudo`를 추측 없이 해석해 Verilog를 생성하는 변환기를 만들기 위한 결정 목록이다.
기존 언어 설명은 [grammar.md](../pseudo/grammar.md), 설계 원칙은 [AGENTS.md](../AGENTS.md)를 따른다.

- **기존 규칙**: 현재 문법에 이미 명시된 사항. 충돌 없이 구현한다.
- **결정 필요**: 현재 규칙만으로 의미나 출력 방법이 충분히 정해지지 않은 사항.
- **권장안**: 검토를 위한 제안이며, 이 문서를 만든 것으로 확정된 규칙은 아니다.

문법을 확정할 때는 grammar.md에도 반영한다. 변환기는 애매한 소스를 임의로 고쳐서
통과시키지 않는다. 현재 CPU를 변환할 수 있는 것은 첫 적용 목표이며, 특정 CPU나
ADD/HALT 프로그램을 알아야 동작하는 변환기를 만들지 않는다.

## 3. 문법과 값의 의미

### D01. 구문 경계와 표현식

기존: comb/seq 선언과 wire 블록, alias, 번들, 배열, 제네릭, 연결 연산자가 있다.

확정(사용자 지시): 줄바꿈은 문장 구분이면서 가독성 공백이기도 하다.
물리적 줄 단위로 문장을 자르지 않는다. 파서가 구문 완성과 다음 토큰의 연속 가능성을
판단한다. 괄호 안뿐 아니라 화살표·연산자·콜론 앞뒤에서도 줄을 바꿀 수 있다.
세부 규칙과 예시는 [문장 경계와 줄바꿈](../pseudo/grammar.md#문장-경계와-줄바꿈)에 반영했다.

구현 시 lexer는 줄 위치를 보존하고, 문장 종료 여부는 parser에서 결정한다.
블록 중괄호와 목록 중괄호를 구분하며 단순 괄호 깊이만으로 판단하지 않는다.
문법상 연속인 경우 이어 읽고, 문장이 완성됐으며 다음 토큰이 이를 이어가지 않으면
새 문장을 읽는다. 임의의 의미 추측이나 예제별 휴리스틱을 넣지 않는다.

결정 필요:

- alias 블록의 쉼표 생략·마지막 쉼표, 주석과 공백의 처리.
- `*`, `+`, `-`의 우선순위와 단항 연산, 정수 리터럴 표기.
- 타입 파라미터의 `*`와 번들 반전의 `*`를 구문별로 구분하는 방법.
- 빈 인덱스 목록·빈 연결 목록 허용 여부.

권장: 현재 쓰인 문법을 EBNF 등으로 명시하고 AST로 분석한다. 괄호 안 표현식은
여러 줄에 걸칠 수 있게 한다. 정규식 치환만으로 HDL을 출력하지 않는다.

### D02. 비트 번호와 목록 전개

기존: `x[a..b]`는 a부터 b-1까지이고, `[ ... ]`는 묶기, `{ ... }`는 각각 연결할 목록이다.

결정 필요: 나열한 요소가 실제 packed vector의 어느 비트에 대응하는지.

권장:

- bit 0을 최하위 비트로 하고, 나열 순서의 첫 요소를 하위 비트에 배치한다.
- `[a,b]`에서 a가 W비트라면 a는 결과의 [0..W], b는 그 위에 배치한다.
- Verilog concatenation은 상위 요소부터 쓰므로 출력 시 순서를 변환한다.
- 범위는 증가 순서로 전개하고, 배열의 필드 선택은 배열 인덱스 순서를 유지한다.
- 중첩 목록, 혼합 인덱스, 중복 목적지, 범위 밖 접근을 명확히 검사한다.

현재의 DFF 배열·ALU 결과 목록·AXI 명령어 바이트 선택이 모두 이 규칙에 영향을 받는다.
메모리의 big-endian 바이트 순서와 비트 묶음 순서는 서로 다른 개념으로 유지한다.

### D03. 폭·상수·게이트

기존: 직접 배선의 양쪽 폭은 같아야 한다. 게이트에 인덱스 목록을 넣으면
각 가닥이 입력으로 전개되며, 벡터 자체를 넣으면 비트별 연산을 한다.

권장:

- 하드웨어 bit/vector는 기본 unsigned이고, signed 산술은 명시적으로 지정한다.
- 상수 계산은 충분한 정밀도의 정수로 수행한다. 신호 폭과 배열 길이는 양수여야 한다.
- 접속 폭이 다르면 오류. 자동 확장·잘림·부호 추측을 하지 않는다.
- 정수 상수는 목적지 폭에 맞춰 명시적인 크기로 출력한다. 표현 불가능하면 오류.
- `word <- 1`은 수치 1, `{ word[..] } <= 1`은 각 가닥 1이라는 구분을 명시한다.
- 게이트 인자는 먼저 가닥/벡터로 전개하고, 결과 폭을 계산한 뒤 연결을 검사한다.
- 빈 reduction, 잘못된 인자 수, 서로 다른 폭의 벡터 게이트는 오류로 한다.

`and(multiplier.hi[..], multiplier.lo[WORD_MSB])` 같은 reduction과 단일 비트 혼합도
명세에 포함해야 한다. 상수 계산 문법과 런타임 하드웨어 연산 문법을 구분한다.

## 4. 연결·이름·순차회로

### D04. 배선과 공유 net

기존: 화살표는 신호 방향이며 `=>`/`<=`는 목록의 각 요소에 같은 신호를 연결한다.

결정 필요: 여러 삼상 출력에서 공통 읽기 버스로 모이는 연결을 같은 문법으로 허용할지.
실제 예는 `general.r1_data <= { generals[..].bus.r1 }`이다.

권장: 연결 목록의 전개와 net의 공유를 내부적으로 분리한다. 위 구문을 공유 버스
연결로 허용할지, 공유 net 전용 문법을 추가할지 명시적으로 선택한다. 포트 방향만
보고 문법의 의미를 임의로 바꾸지 않는다. 일반적인 여러 출력 충돌은 D10으로 검사한다.

### D05. 번들과 InOut

기존: 번들 방향은 소유 소자 기준이고 `*`는 In/Out 반전이다.

권장:

- 번들을 leaf 포트로 재귀 전개한다. InOut은 반전해도 InOut으로 유지한다.
- 현재 모듈의 입력과 자식 인스턴스의 출력은 내부 배선에서 모두 신호 공급원이 될 수 있다.
  이처럼 포트 소유 위치를 고려해 연결 방향을 검사한다.
- `<=>`는 양방향 assign 두 개가 아니라 공유 net 연결로 해석한다.
- 복합 번들 전체 연결을 지원한다면 leaf 이름·타입을 맞춘 뒤 방향별로 연결한다.
- `*`는 별도 포인터 저장소나 런타임 참조를 만들지 않는다.

### D06. 이름·가시성·alias

기존: 폴더가 이름 공간이며 같은 폴더의 여러 파일은 하나의 이름 공간을 공유한다.
global의 요소는 전역에서 접근한다. 하위/형제 경로 표기는 grammar.md를 따른다.

결정 필요:

- 지역 alias, 같은 폴더 이름, global, 내장 이름의 탐색 우선순위.
- `alias TriState = TriState<64>`의 오른쪽이 내장을 뜻하는 규칙.
- 파일 수집 순서와 무관한 전방 참조, alias 순환, 중복 이름 처리.
- 타입과 값의 이름 공간, 인스턴스 이름과 폴더 이름이 같은 경우의 처리.

권장: 먼저 선언을 수집하고 이름을 해석한다. 내장 이름을 명시할 방법 또는
같은 이름의 기본형 alias에 대한 예외를 정하고, 일반 alias 순환은 오류로 한다.
사용자 이름을 코드 생성기 안에서 개별 하드코딩하지 않는다.

### D07. comb·seq·mut와 저장

권장:

- comb와 seq 모두 Verilog module로 출력한다. seq 전체를 클록 always 블록으로 바꾸지 않는다.
- DFF만 표준 라이브러리에서 클록 에지의 nonblocking 대입으로 저장한다.
- 조합 배선은 클록·리셋을 자동 삽입하지 않는다. reset은 소스에 적힌 회로를 따른다.
- 순차 소자를 포함한 comb는 오류. 순차 소자의 간접 포함도 검사한다.
- 사용자 seq 인스턴스에 mut를 요구하는 기존 규칙을 유지한다면,
  현재 mut 없이 선언한 내장 DFF를 예외로 둘지 소스를 수정할지 결정한다.
- 조합 루프와 순차 피드백을 구분하고, 조합 루프는 초기 지원 범위에서 오류로 한다.

## 5. 내장 소자와 미정의 상태

### D08. 표준 소자 계약

| 소자 | 확정할 계약의 권장안 |
|---|---|
| D_FlipFlop | 1비트, 상승 에지 저장, 내장 reset/초기값 없음 |
| Mux<n,m> | m비트 n개, 선택 폭 max(1, ceil(log2(n))), 조합 선택 |
| Decoder<i,o> | i비트 입력, 해당 출력 하나만 1. 입력이 o 이상이면 모두 0 |
| TriState<N> | enable=1이면 데이터 구동, 0이면 Z. 공유 net 규칙과 함께 정의 |
| Adder<N> | 입력 a/b N비트와 c_in, N+1비트 합에서 sum/c_out 분리 |
| Multiplier<N> | unsigned 또는 2의 보수 signed 곱. 2N비트 결과를 hi/lo로 분리 |
| Divider<N> | 2N비트 dividend와 N비트 divisor의 unsigned 조합 나눗셈 |

추가 결정:

- Divider의 quotient/remainder를 N비트로 정할지, 몫이 넘칠 때 어떻게 출력할지.
- divisor=0, unknown 입력에서 내장 소자가 내놓을 값과 시뮬레이션 의미.
- Multiplier의 signed 포트에 따른 연산은 출력 폭과 signed cast를 명시해 구현할 것.
- 소자는 처음부터 조합/순차와 지연 계약을 가진다. 긴 나눗셈 회로를 변환기가
  임의로 여러 사이클짜리 IP로 대체하지 않는다. 변경하려면 소스 인터페이스도 바꾼다.

조합 회로를 합성할 수 있다는 것과 목표 클록을 만족한다는 것은 별개다.
자동 파이프라인 삽입은 초기 변환기의 기능에 포함하지 않는 것을 권장한다.

### D09. OPENED와 Mux 미정의 선택

현재 OPENED는 출력 버리기와 Bitwise Mux의 미구현 입력에 모두 쓰인다.
둘을 하나의 Verilog 상수로 치환하면 안 된다.

권장 구분:

| 위치 | 처리 제안 |
|---|---|
| 출력 → OPENED | 미사용 출력으로 기록. 빈 포트 또는 미사용 net으로 출력 |
| 입력 ← OPENED | 명시적 열린 입력으로 기록. Z로 할지 오류로 할지 결정 필요 |
| 아무 연결도 없는 필수 입력 | 오류 |
| Mux 범위 밖 select | 표준 소자의 기본 결과를 명시. X/정의된 기본값 중 결정 필요 |
| 의도적으로 사용하지 않는 Mux option | OPENED 또는 별도 미정의 표기의 허용 정책 결정 |

X는 시뮬레이션의 미정 값이고 합성에서는 don't-care로 최적화될 수 있다.
따라서 X로 출력한다고 실제 하드웨어가 오류를 검출하는 것은 아니다.
안전한 0 또는 오류 출력을 원하면 그 동작을 회로에 명시해야 한다.

DirectReg의 동시 버스/직접 쓰기는 현재 select=3이다. 이는 회로 설계의 우선순위
결정 사항이다. 변환기가 임의로 어느 쓰기를 우선시하지 않는다.

### D10. 다중 구동과 FPGA 삼상 버스

권장:

- 일반 출력 둘이 같은 비트를 구동하거나 상수와 출력이 충돌하면 오류.
- 명시적 삼상 출력들이 공유하는 net은 일반 중복 구동과 구분해 허용.
- 구동기 전부 꺼짐/여러 개 켜짐의 의미를 정의하고, 이를 숨기는 OR나 우선순위 Mux로
  변환기가 임의 치환하지 않는다.
- initial backend는 공유 net과 삼상 구동 의미를 보존하는 RTL을 출력한다.
- 내부 삼상을 Mux로 바꾸는 별도 최적화는 구동 enable과 상호배타 조건 등을
  다룰 수 있을 때 추가한다. 외부 InOut과 내부 공유 버스를 구분한다.

FPGA 내부 삼상 표현은 실제 내부 삼상 자원이 유지된다는 보장이 아니다.
대상 합성기의 지원 범위와 논리 변환은 별도 고려 사항이다.

## 6. 출력 형태와 변환기 구조

### D11. 제네릭

결정할 출력 방식:

- parameter와 generate를 가진 Verilog 모듈로 유지.
- 사용된 구체 파라미터 조합별로 특수화한 Verilog 모듈 생성.

권장: 중간 표현에 원본 템플릿과 구체 파라미터 인스턴스를 모두 보존한다.
첫 출력기는 구체 특수화를 사용하면 폭 검사와 비트 연결 전개가 단순하다.
예를 들어 ShiftStep<1>, ShiftStep<2>는 서로 다른 구체 모듈로 출력한다.
같은 타입·인자 조합은 한 번만 출력한다. 이는 예제별 하드코딩과 다르다.
parameter 출력으로 확장하더라도 파서와 의미 분석기를 교체하지 않게 한다.

### D12. Verilog 버전·파일·모듈

권장: 초기 출력은 Verilog-2001의 일반 포트와 wire/module을 사용한다.
SystemVerilog interface/package를 필수로 하지 않는다. SystemVerilog를 선택하려면
출력 확장자와 지원 문법을 별도로 명시한다.

기본 구성은 **원본 폴더 구조 유지 + 회로 정의 하나당 Verilog module 하나**다.

```text
generated/
  cpu/
    Cpu.v
    alu/
      Alu.v
      ExcCheck.v
      ShiftStep__K_1.v
    reg/
      Registers.v
  builtin/
    ...
  sources.f
  source-map.json
```

- 같은 이름의 comb/seq와 wire 블록은 결합해 module 하나로 출력한다.
- 폴더는 이름 공간이다. 폴더 자체를 회로 module로 만들지 않는다.
- bundle은 포트 구조이고 alias는 이름/상수다. 각각을 회로 module로 만들지 않는다.
- module명에는 경로와 필요 시 구체 파라미터를 포함한다.
- 경로/포트 펼치기의 이름 충돌과 Verilog 예약어는 일관된 escape/인코딩 규칙으로 처리한다.
- 단일 파일 출력은 동일한 module들을 정렬해 합치는 선택 기능으로 둔다.
  단일 파일 출력과 회로 계층 flatten은 별개이며 계층 flatten은 기본으로 하지 않는다.
- 보드 MIG IP와 래퍼는 사용자 소스 영역에 둔다. 변환기가 생성하지 않은 파일은 덮어쓰지 않는다.

### D13. 진단

권장: 파싱/이름/타입/폭/방향/net 검사를 분리하고 원본 파일·행·열을 유지한다.
아래는 정적 오류의 예다.

- 타입/포트 이름 없음, alias 순환, 중복 회로 정의.
- comb/seq와 wire 짝이 없거나 중복됨.
- 배열 범위 초과, 폭 불일치, 중복 목적지, 미연결 필수 입력.
- 일반 다중 구동, 방향 위반, 조합 순환, 재귀 회로 인스턴스.

예상 폭과 실제 폭, 관련 연결 위치를 함께 보고한다. 경고를 출력한 뒤 임의의
회로로 보정하지 않는다. 미지원 구문은 어떤 구문인지 명시하고 실패한다.

### D14. 결정론적 출력

동일한 소스·변환기 버전·옵션·표준 소자 버전이면 동일한 바이트를 출력한다.

- 입력 경로와 선언 처리 순서, 인스턴스 번호와 임시 net 이름을 고정한다.
- 실행 시각·사용자 절대 경로·난수·해시 컨테이너 순서를 결과에 넣지 않는다.
- 생성 파일의 인코딩/줄바꿈과 이름 규칙을 고정한다.
- sources.f에 생성 파일 목록과 순서를 기록하고 top module을 명시한다.
- source-map.json으로 생성 모듈/포트/net과 원본 선언·배선을 연결한다.
- 모든 분석이 성공한 뒤 결과를 반영한다. 실패로 반쪽짜리 출력이 남지 않도록 한다.
- 오래된 생성물 삭제는 생성 manifest에 기록한 전용 출력 디렉터리 안에서만 한다.
- 파일 합치기 옵션도 동일한 회로 중간 표현을 사용한다.

### D15. 프로그램 구성과 구현 순서

권장 구성:

```text
입력 수집 → 파서/AST → 이름 해석 → 타입·상수·폭 계산
         → 번들·배열·제네릭 구체화 → net/구동기 분석 → 회로 IR → Verilog 출력
```

초기 구현에서도 각 단계의 책임을 나눈다. CPU 명령어를 해석하거나 현재 프로그램의
기대 결과를 계산하는 코드를 변환기에 넣지 않는다. 논리 최적화는 초기 필수 사항이 아니다.

구현 언어는 아직 미정이다. 초기 권장안은 Python의 파서·타입 자료구조·CLI이며,
Vivado 프로젝트 조작이나 합성을 변환 명령의 기본 부수 동작으로 넣지 않는다.

권장 진행 순서:

1. D01~D10을 확정하고 grammar.md와 소자 계약에 반영.
2. 소스의 의미 분석과 오류 보고를 먼저 구현.
3. 일반 회로 IR과 표준 소자 출력을 구현.
4. 폴더/모듈 출력과 manifest/source map을 구현.
5. 현재 CPU에 적용하며 문법 위반은 소스를 수정하고 변환기에서 특례를 만들지 않음.
6. 단일 파일 출력 등 편의 기능은 같은 IR 위에 추가.

동작 검증은 사용자의 명시적 요청이 있을 때만 수행한다. 변환기의 정적 의미 분석은
변환 자체의 필수 단계이며, 회로 시뮬레이션·합성·보드 실행과 구분한다.
